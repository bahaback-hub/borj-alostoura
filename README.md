# منظومة برج الأسطورة — إدارة عمليات فرع مطابخ المدينة المنورة

منظومة إدارة عمليات فرع مطابخ **المدينة المنورة** المرتبط بمصنع **القصيم**.
تطبيق ويب ثابت (HTML + Tailwind CSS + JavaScript) عربي بالكامل مع دعم RTL، يستخدم **GitHub API كقاعدة بيانات مجانية** عبر قراءة وتحديث ملف `data/contracts.json` داخل المستودع.

> **الوضع التجريبي:** يمكنك تجربة التطبيق فورًا بدون أي إعداد — يعمل تلقائيًا في «الوضع التجريبي المحلي» ببيانات محفوظة في متصفحك حتى تربطه بـ GitHub.

---

## بنية المشروع

| المسار | الوظيفة |
|---|---|
| `index.html` | الواجهة الكاملة (تبويبات: العقود، عقد جديد، المستودع واللوجستيات، البحث في الصيانة) |
| `app.js` | المنطق البرمجي، ربط GitHub API، قفل رفع الرسمة، إدارة الحالات والصلاحيات |
| `assets/app.css` | أنماط Tailwind **المبنية** (لا تُحرّرها يدويًا — تُولَّد من `src/input.css`) |
| `src/input.css` | المصدر: أصناف Tailwind المخصّصة + الأنماط العامة |
| `tailwind.config.js` | ألوان المنظومة (ink/gold/mist) والخطوط |
| `data/contracts.json` | **قاعدة البيانات الفعلية** (تبدأ فارغة: `contracts: []`) |
| `data/sample.json` | بيانات تجريبية للعرض فقط — انسخ محتواها إلى `contracts.json` إن أردت التجربة |
| `scripts/check-json.mjs` | التحقق من صحة ملفات JSON ومنع تكرار معرّفات العقود |
| `scripts/smoke-test.mjs` | تأكيد أن كل معرّف/زر في الكود موجود ومربوط (بلا متصفح) |
| `scripts/portal-test.mjs` | فحص بوابة الفنيين في DOM حقيقي (jsdom): العرض، الإخفاء، وإتمام التركيب |
| `drawings/` | يُنشأ/يُستخدم تلقائيًا عند رفع ملفات رسمات المصنع (حتى 900KB لكل ملف) |

## 1) البناء المحلي (للمطوّر)

يتطلب [Node.js](https://nodejs.org) الإصدار 18 أو أحدث.

```bash
npm install          # مرة واحدة
npm run build:css    # يبني assets/app.css من src/input.css
npm run watch:css    # إعادة البناء التلقائي أثناء التطوير
npm run check        # فحص JSON + ESLint + فحص الدخان + فحص بوابة الفنيين (jsdom)
```

> **ملاحظة:** `assets/app.css` مُودَع في المستودع حتى يعمل الموقع على GitHub Pages دون خطوة بناء.
> إن عدّلت `index.html` أو `app.js` وأضفت أصناف Tailwind جديدة، شغّل `npm run build:css` قبل الرفع.

---

## 2) النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub (مثال: `borj-alostoura`).
2. ارفع الملفات إلى الفرع `main`.
3. من إعدادات المستودع: **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**.
4. بعد دقيقة تقريبًا سيصبح التطبيق متاحًا على:
   `https://<اسم-حسابك>.github.io/borj-alostoura/`

> يمكن أيضًا استخدام سير النشر الجاهز في `.github/workflows/deploy.yml` الذي يبني CSS ويرفع الموقع تلقائيًا.

## 3) تفعيل قاعدة البيانات (GitHub as Database)

1. أنشئ رمز وصول شخصي (PAT) بصلاحيات محدودة:
   - GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
   - **Repository access**: اختر «Only select repositories» ثم مستودع المنظومة فقط.
   - **Permissions → Repository permissions → Contents**: `Read and write`.
   - مدة الصلاحية: حدد مدة مناسبة وذكّر نفسك بتجديدها.
2. افتح التطبيق → زر **الإعدادات (⚙)** → املأ:
   - مالك المستودع (Owner)، اسم المستودع (Repo)، الفرع (`main`)، مسار الملف (`data/contracts.json`).
   - الصق رمز الوصول (PAT).
3. اضغط **اختبار الاتصال** ثم **حفظ الاتصال**.

من هذه اللحظة كل عملية (عقد جديد، دفعة، رسمة، وصول، إسناد، تذكرة صيانة) تُحفظ كـ **Commit** مباشر في المستودع، وتظهر فورًا لجميع الأجهزة المتصلة (مع تحديث تلقائي خفيف وزر تحديث يدوي).

> **ملاحظات أمنية مهمة**
> - الرمز يُخزَّن في `localStorage` متصفح كل مستخدم فقط (هذا ما يسمح به الموقع الثابت)، لذا استخدم رمزًا محدود الصلاحيات على مستودع المنظومة فقط.
> - الصفحة محميّة بسياسة أمان محتوى (CSP) تحدّ من أثر أي ثغرة XSS، لكنها ليست بديلًا عن رمز محدود الصلاحيات.
> - لتطبيق داخلي بفريق موثوق هذا مقبول؛ ولرفع المستوى الأمني استخدم حسابًا مخصصًا للمنظومة.
> - لعرض ملفات الرسمات المرفوعة مباشرةً يفضَّل أن يكون المستودع **عامًا**؛ وإلا استخدم الروابط الخارجية (Drive/Dropbox).

## 4) الأدوار والصلاحيات

يتم اختيار الدور من موجه بسيط عند الدخول أو من زر «تبديل الدور» في الأعلى:

| الدور | الصلاحيات |
|---|---|
| **المدير العام / المشرف** | كل شيء: تسجيل الدفعات، **تجاوز قفل رفع الرسمة**، بدء الشحن، تأكيد الوصول، الإسناد، الاعتماد النهائي لإغلاق الملف، إغلاق تذاكر الصيانة، تعديل إعدادات الفريق |
| **المصمم** (أبو جمال، أبو يزن، علاء، خالد) | فتح العقود، تسجيل الدفعات، رفع رسمة المصنع **فقط بعد السداد الكامل** |
| **مدير المستودع** | تأكيد «تم الوصول إلى مستودع المدينة»، إسناد الطلبات لفنيي التركيب (اسم الفني كتابةً حرة مع اقتراحات) |
| **فني التركيب** | الدخول من **بوابة الفنيين** (بلا حساب) لرؤية كل عقود التركيب مع رسمة المصنع وبيانات العميل وموعده، وتأكيد «تم الانتهاء من التركيب» أو «يحتاج بعض التشطيبات» |

### بوابة الفنيين

- من شاشة الدخول يوجد زر **«بوابة الفنيين»** بلا كلمة مرور أو اسم مستخدم.
- تعرض البوابة **كل العقود قيد التركيب** (المسندة + المكتملة تركيبًا) مع: رقم العقد، رسمة المصنع (رابط فتح/تحميل)، اسم العميل، عنوانه، جواله، والموعد/المهلة.
- زرّا الفني: **«تم الانتهاء من التركيب»** و**«يحتاج بعض التشطيبات»** — أي ضغطة تُرفع كـ Commit فورًا في المستودع فيراها المدير والمشرف والمصممون خلال ثوانٍ (زر تحديث + تحديث تلقائي).
- يمكن مشاركة رابط مباشر للبوابة بإضافة `?tech=1` إلى العنوان، مثل: `…/borj-alostoura/?tech=1`.
- **لتشغيل الحفظ الفوري في المستودع:** ضع رمزًا (Fine-grained PAT مقيّد بمستودع المنظومة وصلاحية `Contents: Read and write`) في الثابت `TECH_SHARED_TOKEN` أعلى ملف `app.js`. عند تركه كما هو (placeholder) تعمل البوابة في **وضع تجريبي محلي** دون رفع إلى GitHub.
  > **⚠️ تنبيه أمني:** أي رمز يُوضع في `app.js` يصبح **مرئيًا لأي زائر** للصفحة العامة، لأن الملف يُخدَّم مكشوفًا. اقتصر على رمز محدود الصلاحيات على هذا المستودع فقط، ولا تستخدم رمزًا واسعًا لحسابك.

## 5) دورة حياة العقد

```
عقد جديد ← دفع العربون ← السداد الكامل ← رفع رسمة المصنع (قفل أمني + عداد 15–40 يوم)
← تصنيع بالقصيم ← شحن (~10 أيام) ← وصول مستودع المدينة ← إسناد لفني
← تم التركيب / يحتاج تشطيبات ← اعتماد المشرف النهائي ← مكتمل (ضمان 15 سنة) ← أرشيف الصيانة
```

- **قفل الأمان**: زر «رفع رسمة المصنع» معطَّل برمجيًا حتى تصبح حالة العقد «مسدد بالكامل» — ويُستثنى منه المدير العام (يُسجَّل التجاوز في سجل العقد).
- **العداد التنازلي**: يبدأ تلقائيًا من لحظة رفع الرسمة (تختار مهلة 15–40 يومًا) مع شريط تقدم وتلوين تحذيري عند اقتراب الانتهاء.
- **ضمان 15 سنة**: يُحتسب تلقائيًا من تاريخ التركيب ويظهر في أرشيف الصيانة.
- **سجل كامل**: كل حركة تُوثَّق باسم المنفّذ والتاريخ في سجل العقد.

---

## 6) أرشيف الصيانة

تبويب «البحث في الصيانة» يوفر بحثًا فوريًا متسامحًا (يتجاهل الهمزات والتاء المربوطة) بـ:
- رقم الجوال، أو رقم العقد (مثل `BRJ-2026-0003`)، أو اسم العميل.
- تعرض النتيجة: كل بيانات العقد، الرسمة، تاريخ التركيب، حالة الضمان، التذاكر السابقة، وزر **فتح تذكرة صيانة جديدة** فورًا.

---

## 7) العمل بدون إنترنت

عند تعذر الاتصال بـ GitHub يعرض التطبيق آخر نسخة محفوظة محليًا (قراءة فقط) بشارة تحذير، ويعود للحفظ الطبيعي فور عودة الاتصال.

---

## 8) تخصيص

- أسماء المصممين ومدة الضمان ومهلة التسليم الافتراضية: من **الإعدادات → إعدادات المنظومة** (للمدير العام) وتُحفظ في المستودع للجميع.
- **أسماء الفنيين** ليست قائمة ثابتة: تُكتب يدويًا عند الإسناد مع اقتراحات تلقائية من الأسماء المُسندة سابقًا (وحقل «أسماء الفنيين المقترحة» في الإعدادات اختياري لتغذية الاقتراحات).
- **بيانات تجريبية للعرض:** `data/sample.json` يحتوي 6 عقود تعليمية. لتجربتها على موقعك، انسخ محتواها إلى `data/contracts.json` (أو أفرغ المصفوفة `contracts: []` لبدء نظيف).
